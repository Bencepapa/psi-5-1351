# Psi-5 Trading Company: mouse support

| Version | File | Status |
|---|---|---|
| **EasyFlash cartridge** (from "PSI-5 +4D 101% ATA", full game with course and crew selection) | `psi5_ef.crt` | current, see below |
| Old preset disk (`PSI5.d64`) | `PSI5-1351_v1.d64` | first version, further down |

## EasyFlash cartridge with mouse (`psi5_ef.crt`)

Build: `python ef/efbuild.py`. Run: `x64sc -cartcrt psi5_ef.crt -controlport2device 3` (1351 in port 2). `Alt+Q` grabs the mouse.

| Input | Effect |
|---|---|
| Moving the mouse | A pointer sprite (sprite 7) on text rows 13-24. Sprite 7 is multiplexed: the ships use it above the split, the pointer below. |
| Click a word on the menu row | Types its shortcut key: departments, Status, Display, `?`, Cancel, Rank, letters, numbers and the back arrow |
| Engineering **Status**: click a device row | Enables or cancels the device (`$95AC`), so it shows RqE/RqC like the menu does |
| Engineering **Display**, Weapons firing orders, Repair fix-it, Scan detailed examination: drag a row to another row | Ranks the item at the new position (`$8AE7`) |
| Navigation **Status**: click a course | Selects it without rank-row flashing |
| Navigation **Display**: click a course | Moves it to position 1; the selected course flashes yellow and shifted rows blue. No drag preview. |
| Scan **Status**: click a target | Examines it (`$8CFC`) |
| Repair **Status**: click a damaged item | Types Assign and its letter; the game then asks how many robodroids |
| A list while the game asks for a letter or number | Types the clicked row's item letter or row number |
| Click outside menus | Fire (for example "Press BUTTON to begin") |
| Joystick, keyboard | Work as before |

**How it fits:**
- The cartridge replaces the Krill disk loader; the mouse RAM part occupies `$0210-$02FF`.
- `$0334-$03F2` can't be used: file loads overwrite it (`dp` loads at `$0374`).
- These hold small trampolines: they map the mouse code's ROM bank (bank 1, 8K mode, `$01=$37`), call it, and switch the cartridge off again.
- The game's routines are called from RAM with the cartridge off.
- Hooks in `mx`:

| Address | Was | Now | Purpose |
|---|---|---|---|
| `$8F2D` | `JSR $8FA5` | `JSR TPRE` | Pots and pointer |
| `$8FB1` | `LDA $DC00` | `JSR TJOY` | Buttons and joystick byte |
| `$9005` | `JSR $3E72` | `JSR TPOST` | Select port 2's pots after the keyboard scan |
| `$8609` | `JSR $3EE9` | `JSR TKEY` | Carry out clicks in the menu loop |
| `$8EFF` | `JMP $8F95` | `JMP TSPR` | Show the pointer at the text split |
| `$8F40` | `STA $D018` | `JSR TTOP` | Restore sprite 7 above the split |
| `$E8C8`, `$E8F1` | `STA $D000,Y` | `JSR WRX` | Sprite X stores |
| `$E8D3`, `$E8FC` | `STA $D001,Y` | `JSR WRY` | Sprite Y stores |
| `$E88A` | `STA $D02B,X` | `JSR WRC` | Sprite colour store |
| `$E90B`, `$92ED`, `$9387`, `$9437`, `$B920` | `STA $D015` | `JSR WRE` | Sprite enable stores |

The pointer is sprite 7, a white arrow with a black outline (multicolour). Nothing in the VIC bank is free, so its block `$82` at `$6080` is a piece of static frame art in the bitmap's top row: the arrow is written there at raster `$82` (hook `$8E9D`), and the art is written back from ROM at `$2D`, first lines first, before the VIC reads it at line 51. Both are unrolled code generated by `efbuild.py`, about 380 cycles each. Rejected: `$5780` (keyboard table), `$7F80` (list pages), `$4580` (ship shapes, read by the renderer at `$EA4D`), `$6540` (space view, redrawn by `$E003`, which runs until about line 257). The text screen at `$5000` has its sprite pointers at `$53F8-$53FF`, so `$53FF` is set to `$5E`. If the first byte at `$5780` changes, the ROM part copies the 63-byte arrow back, so a load that overwrites it is repaired. While the text area is on screen, the game's stores for sprite 7's X, Y, colour and enable go to shadow variables; at the top of the next frame `TTOP` puts the ship's sprite 7 back.

A menu-row hover now drives the game's own left/right selection until its cursor column at `$0774` matches the word under the pointer. The game paints the sole white highlight, so keyboard, joystick and mouse all share one selection. Clicking a valid menu word fires that native selection; lowercase prompt/suffix labels and separator cells stay cyan, are not selectable, and do not fire. A menu click is no longer translated by scanning the rendered word for its first character.

On a list row, the mouse still finds the item letter in the clicked column (including the two-column device lists). If the game is asking for a letter or number, it types the clicked item letter or row number. Otherwise it acts by the screen title: Engineering Status toggles a device, Navigation selects a course, Scan Status examines a target, Repair Status types Assign and its letter, and the priority lists rank on a drag. Before acting it saves `$2D-$3A` in `RECBUF` and restores it afterwards, so a half-typed command survives.

**Sources:** `ef/mouse_ram.asm`, `ef/mouse_rom.asm`; the cartridge itself is `ef/ef_boot.asm`, `ef/ef_res.asm` and `ef/efbuild.py`.

List recognition still reads the rendered item letters and title; the original game does not register mouse rectangles when drawing tables. `ROWADR` now uses fixed row-offset tables. List hover, drag preview and flash painting run once per pending frame from `MKEY`, starting on PAL raster lines 240-295. `ROMCALL` masks interrupts while mapping ROML, so this work is restricted to that window. The split IRQ retains pointer/input work and native menu targeting. Flash setup and restoration paint one row per update. `HOVE` stores either a list's end column or the native menu pulse phase; joystick polling resets it only for native menu targets, preserving list bounds.

Navigation uses the native `$8AE7` routine, which selects position 1. Status selection suppresses rank feedback; Display selection retains it. A new rank during an existing flash keeps `BASEC` and merges the old and new row ranges, so every previously painted row is eventually restored even if a list item disappears.

**Feedback:** on the menu row, the game's native active selection follows the pointer and is the only white highlight. List-row clicks retain their own white row/column preview; a dragged row in a priority list turns grey and the row under the pointer yellow, the row it would land on. After the rank the moved row flashes yellow and the shifted rows blue for 40 frames. Clicking the back arrow, or the right button anywhere in the bridge menus, goes back; during a drag the right button cancels it. The trainer prompt and crew selection don't have this: they use another key queue.

**Tested in VICE** (mouse moves and clicks simulated through the monitor; there is no automated test with a grabbed host mouse):
- the pointer moved;
- a click on "Display" and on "Status" switched lists;
- a click on Port Shield set it to "no";
- a drag of class F to the first row ranked it 1.

Only the Engineering lists have been tested so far.

**Not done yet:**
- mouse in port 1;
- QUIT/restart (it loads from disk).

## How it plays

| Input | Effect |
|---|---|
| Mouse (port 1 or 2, found automatically) | A pointer sprite. It is hidden when there is no mouse. |
| Pointer over a menu word | The game's own highlight moves to that item. The pointer turns yellow with a "!". |
| Left click on a menu word | Selects it, like moving there with the joystick and pressing fire |
| Left click anywhere else, outside menus | Fire (e.g. "press fire to continue") |
| Left click in a menu but not on a word | Ignored |
| Joystick in port 2, and the keyboard | Work as before, also together with a mouse in port 1 |

## This disk

The disk is a cracked release, `HEADBANGER PRESENTS`, with a packed loader
(the BASIC stub says "compressor – written by Wutz") and three parts:

| File | Load address | Contents |
|---|---|---|
| `psi 5 trading c.` | `$0324` | Packed loader, autostarts through the vectors |
| `part1` | `$E000-$FFFF` | RAM under the KERNAL |
| `part2` | `$A000-$CFFF` | RAM under BASIC |
| `part3` | `$1000-$9FFF` | Main code and graphics, stored unpacked |

During play the BASIC ROM is switched off (`$01=$36`), and no BASIC runs.

The game starts directly on the bridge, with a fixed situation (the repair
crew reports the "survolater" is fried). Memory holds no text for crew
hiring, missions or cargo, but it does hold a loader prompt, `ON WHICH SIDE
STANDS FLASH ?`. This image is probably one side of a two-sided release, or a
cut-down crack, so the crew selection and mission briefing of the full game
are missing here.

## How the game reads input

| Part | Where | What it does |
|---|---|---|
| **One joystick read per frame** | top-of-screen raster IRQ, `$864E` | `JSR $FF9F` (keyboard scan), then DDR A = 0, `LDA $DC00` at `$86A9`, `AND #$1C` (port 2: left, right, fire only). Held bits go to `$1035`, newly pressed bits to `$1034`. |
| **One menu routine for every menu** | `$81E8` | Prints the items as words on text row 14 (`$5231`). The item count is in `$1008`, the current item (1-based) in `$103A`. |
| **One input loop** | `$8249` | `JSR $FFE4` (keys) first, then `$1034`: fire selects, left/right step the highlight. It is the game's only `GETIN`. |
| **Sprites** | – | Never used (switched off at start-up) |
| **Screens** | VIC bank 1 | Text screen at `$5000`, the bitmap's colour screen at `$5400` (both need the sprite pointer), custom font at `$5800`, bitmap at `$6000` |

## The patch

Hooks in `part3`:

| Address | Was | Now | Purpose |
|---|---|---|---|
| `$869D` | `JSR $FF9F` | `JSR MPRE` | Read the pots before the keyboard scan, move the pointer, then do the keyboard scan |
| `$86A9` | `LDA $DC00` | `JSR MJOY` | Return the port-2 lines the game should see |
| `$8249` | `JSR $FFE4` | `JSR MLOOP` | Mark "a menu is waiting" for 6 frames, then `GETIN` |

**MJOY** runs while DDR A = 0. It writes the mouse port's pot selection
(`$7F`/`$BF`) into the `$DC00` latch. The game restores DDR A right after, so
the pots stay selected for the whole frame, and the next IRQ reads them before
the keyboard scan. It then builds a virtual joystick byte:
- **In a menu with the pointer on a word:** it finds the item number by
  counting words in the screen row up to the pointer's column. While that
  differs from `$103A` it presses "right" or "left" every second frame. The
  game's own code moves the highlight, wrap-around included. A click is held
  back until the highlight has arrived, and then becomes one fire press.
- **Outside menus:** the left button is fire.
- **A mouse in port 2:** its own fire and up lines (left and right button) are
  masked out, so only the patch decides what they do.
- **A mouse in port 1:** its buttons would type ghost keys, so the keyboard
  buffer is emptied while they are pressed.

The 1351 code is shared with MOUSEGUI: CBM MOVCHK, and auto-detect through
`$FF` pots, alternating ports until one gives real values.

**Where the code lives:** `$7808-$7AE4` (733 bytes) holds the code, and
`$7F80-$7FFF` the two pointer shapes (sprite blocks `$FE`/`$FF` in bank 1).
This is the unused end of the bitmap. It was verified before use: it is zero
in the file and at run time. It was filled with a marker, and 227 random
joystick actions in warp mode visited several departments and sub-menus.
Afterwards the marker was intact (as were `$0200-$0281`, `$02A7-$0313` and
`$0334-$03FF`). `build.py` stops if any patch byte lands on a non-zero byte
of the original or outside that area.

`part3` is rewritten in its own sectors, so the loader finds it however it
reads the disk.
